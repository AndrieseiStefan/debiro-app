# Document management (E1-029 / E1-029A / E1-029B / E1-029C)

[Canonical mockup 29](../design/mockups/29-document-actions-and-details-entrypoints.png) adds shared document interactions without redesigning the Global Documents or Vendor Details tables. Document names/types, not filenames, are the primary links. Current Needs Review records open the existing `/documents/[id]/review` flow; other records open the same `DocumentManagementDrawer` over either listing. RO/EN use locale-preserving client navigation. Drawer URLs use `?document=<id>` with optional `documentAction=replace|history|success`; closing restores the owning listing. Browser Back, Escape, focus trapping/return and scroll locking reuse the shared Drawer.

Uploaded-document menus contain Open details, Replace/renew, View history and Download. Global Documents also offers Open vendor using stable `vendorId`. Vendor Details keeps requirement removal in a separate shield control; the document menu never mutates requirement configuration. Missing rows retain Upload and requirement actions, without fake document links/history/downloads.

## Canonical details and drawer navigation (E1-029A/B)

[Document Details](../design/mockups/document-details.png) supersedes mockup 29's Details presentation. The shared Drawer has an 804px desktop panel, 28px content padding and file/information plus action/preview columns without a vertical separator. At reduced widths the sections stack in that order. Shared shell, close, overlay, animation, focus trap, Escape and scroll locking remain unchanged; Button, StatusBadge, typography tokens and shared icons are reused.

The file card displays filename, human-readable type, actual size when available and Download. Its unavailable-file explanation is subdued. Exactly six information rows appear: Name, Requirement, Compliance status, Expiry date, Uploaded at and Uploaded by. E1-029B removes Notes from this presentation without removing stored notes. Vendor, source, version, document number, issue date, issuer and passive review metadata remain in the domain model but not in primary Details. Compliance badges use one semantic icon through the shared StatusBadge's opt-in `indicator="none"`; unrelated dot badges keep their default appearance. Real upload timestamps are shown; date-only fixture provenance remains date-only. Current Needs Review details retain an explicit Review link.

The bordered Actions card presents Replace document using the existing internal renewal flow. Canonical Mark as expired and Delete document controls are visibly disabled and explain that no approved behavior exists; no expiry mutation or general deletion is implemented. Details preview contains at most three actual recent versions, with version circle, known upload date/time, actor and Current only on the actual current version. It does not repeat filename, compliance status or expiry.

Full History follows mockup 29's compact vertical timeline: circular markers (emphasized for the actual current version), version/date/actor on the left, outcome/actions on the right, row separators and only a subtle current-row highlight. Current versions show the Current version label; approved historical versions show known validity dates. Internal renewals retain the truthful Internal update — no review outcome rather than claiming human approval. Rejected versions show Rejected, without irrelevant expiry information. The current domain has no stored rejection reason, so none is invented from notes, dates or audit copy. No filename, general metadata, reviewer rows or repeated unavailable-file helper appears in History. Download is shown only for actual historical files; every version's shared three-dot menu offers Open details and Download only if actual bytes exist. On mobile the right-side information reflows below version provenance while retaining the timeline.

Details → View all → History → Back returns to the same selected Details context. History → version menu → historical Details → Back → History → Back → original Details uses a small internal navigation stack in one mounted Drawer, not nested drawers or new routes. A direct history URL starts with a Details return target. Internal transitions preserve the entry URL, owning page/vendor and tab-memory records; each transition resets panel scroll and focuses the new heading. History menus opt into a dialog-contained portal so shared focus trapping includes their actions; opening a menu preserves panel scroll even in short viewports. Escape closes an open menu and restores its trigger before it can close the drawer. Otherwise X/Escape closes the whole drawer and restores the original trigger. Replacement success still updates the URL to the new current identity as in E1-029.

## Current versions and internal updates

Initial records without seeded history implicitly have version 1 and a version group equal to their ID. E1-029C's existing Construct Pro ISU fixture has approved current v2 and superseded v1 for two-entry preview/timeline validation; see [fixture data](../project/fixture-data.md). Later versions carry `versionGroupId`, ordered `version`, `previousDocumentId` and a distinct ID. Successful internal replacement sets `supersededById` on the old record without overwriting its file, metadata or review outcome. The new file becomes current; a configured VendorRequirement atomically references it with supplier-facing Uploaded. Unassociated documents remain unassociated; renewal does not fabricate a requirement.

The internal transaction validates the active membership, company/vendor ownership, current identity/reference, PDF/JPG/JPEG/PNG and 10 MB rules, real supplied DD.MM.YYYY dates and chronology. Number, dates, issuer and notes are optional, matching Add Document semantics. It derives Valid/Expiring Soon/Expired with the existing warning period and fixture clock, never Needs Review solely for an internal update. `updateSource=internal` distinguishes acceptance without review from human-reviewed documents; no reviewer metadata or authoritative verification is fabricated. One `document_replaced` audit event records actor ID/name, company/vendor/requirement IDs, previous/new IDs and versions, timestamp and localized action. Vendor Activity and Notifications/Audit reuse that event, without creating delivered/unread notifications.

`activeDocuments` excludes both superseded and rejected records. Global/Vendor rows, counters, search/filter/sort, vendor compliance/completion/next expiry, Dashboard and Notifications projections consume current records only. Configured-requirement compliance rules and zero-requirement Compliant behavior are unchanged. Historical records keep their original outcome/status and never satisfy the current requirement. Superseded pending files cannot be reviewed through stale URLs.

Supplier upload remains Missing → In Review and document Needs Review. Rejection retains the upload and clears the current requirement reference. A subsequent supplier upload joins that requirement's version chain with a new ID and still requires approval. Initial Add Document review/extraction semantics are unchanged. Neither path parses arbitrary file contents or performs OCR/AI.

## Access and file limits

Existing active company memberships provide local E1 checks: Administrator can replace/renew and review; Reviewer can review; Viewer can read but cannot replace/renew or review. The existing role contract does not grant Reviewer document-management permissions. Details/history/download selectors and mutation boundaries reject foreign companies, inaccessible vendors, stale/current-reference mismatches and inactive memberships. These browser checks are not server authentication or authorization.

Actual selected File/Blob objects are retained only in a private tab-memory map, separate from serializable document metadata. Current and historical local files can be downloaded with short-lived object URLs; access is rechecked before download. Fixture records have no supplied bytes: Details disables Download with a subdued explanation; History omits unavailable downloads without repeated explanations. No fake file content is generated. Refresh or another tab loses local records/files; no API, remote upload, durable/private object storage, real PDF viewer, scanning or backend audit is introduced.
