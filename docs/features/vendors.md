# Vendors list (E1-004)

The directly accessible `/vendors` and `/en/vendors` routes implement the authenticated Vendors List from [mockup 04](../design/mockups/04-vendors-list.png). Romanian mockup copy is preserved with temporary branding handled by the shared text-only `DEBIRO` shell; English copy remains subject to product-owner review. The canonical image is unchanged.

`VendorsListPage` receives a typed `VendorsListViewModel` from `src/features/vendors/fixtures.ts`. Its 24 deterministic sample suppliers initialize identities, not independent compliance/count/expiry truth or durable persistence. The shared [E1 fixture projections](../project/fixture-data.md) derive configured-vendor compliance, current completion and next expiry from the same requirements/documents used by Details. Unconfigured vendors remain Attention with actual current file counts, without fabricated requirements. The page reuses `AuthenticatedAppShell` and now composes the shared `AuthenticatedPageHeader` with semantic breadcrumbs and a primary action. It also reuses the shared Furnizori navigation, global search, utilities, organization context, `Button`, `Surface`, and `StatusBadge`; it does not create another authenticated shell or sidebar.

The Vendors-specific search, category and compliance-status selectors, page-size control, and pagination operate locally on fixture rows and any [locally created vendors](add-vendor.md). E1-026A makes every vendor name a locale-preserving [Vendor Details](vendor-details.md) link; rows themselves are not clickable. Each ellipsis opens a two-action context menu: Open Supplier and Mark Inactive (or Mark Active). The menu supports keyboard entry, arrow/Home/End navigation, Escape with focus return, Tab exit and outside-click dismissal; its viewport-clamped portal avoids clipping inside the scrollable table. Unsupported bulk-selection checkboxes/state are removed. E1-027A replaces the inline selectors and unavailable additional-filter control with shared `SearchInput`, `FilterTrigger` and `FilterPanel`. Category and **Status conformitate** retain stable IDs; filters apply immediately, expose an active count excluding search and Reset clears filters only. The panel is an anchored desktop popover or shared mobile Drawer; see the [search/filter contract](../design/ui-foundation.md#authenticated-search-and-filters-e1-027a). The shell's global search still accepts typing only. No authentication, API, database, or provider integration exists.

E1-026A1 activates the five existing sortable headers. The initial fixture order is unchanged until a header is activated; first activation sorts ascending, the next descending, and a different column starts ascending. Native buttons support keyboard activation; the active header exposes `aria-sort` and a distinct direction indicator. Actions is not sortable. Search/filters run before sorting, then pagination; changing sort resets page 1. Names use normalized locale-aware A–Z/Z–A comparison; categories use the displayed localized label; compliance uses compliant → attention → noncompliant severity (reversed descending); documents use completion ratio with zero required treated as zero; expiry uses the explicit ISO calendar date, never the display label. Missing expiries are last in either direction. Equal primary values use normalized name ascending, then stable identity for identical names. Lifecycle is not a sort key: inactive rows keep their recorded compliance and other sort values. Sorting is page-local and introduces no persistence or new filters.

`lifecycleStatus` (`active`/`inactive`) is separate from the current `status` compliance projection (`compliant`/`attention`/`noncompliant`). The existing `created-vendors.ts` browser-memory store holds lifecycle and saved metadata for seeded and created vendors. Changes survive client navigation and locale switching, not reload. Inactive rows remain searchable/filterable, navigable and interactive with a neutral badge/background, without erasing vendor data or documents. All counts every listed vendor; compliance summary cards count only active vendors. The compliance filter uses the current projected status, including inactive rows; lifecycle does not change compliance. E1-026B metadata editing is available only from Details, not the row menu. Saved name, CUI, contact person and category feed the existing list projection, search, filters and sorting immediately; vendor metadata edits do not change requirement/document state. E1-028 approval/rejection updates configured-vendor compliance/counts immediately; next expiry and unconfigured file counts also derive from current records. No lifecycle filter, deletion/archive, invitation change or template assignment is introduced.

The table keeps its mockup-like columns and scrolls inside its own focusable region when they cannot fit; the document does not scroll horizontally at the validated desktop, tablet, reduced-shell, mobile, or 320px widths. The closing mountain banner reuses the existing generated artwork, so its painting is an approximation of the mockup. Generated captures in `artifacts/visual/` are ignored, unapproved comparison artifacts. A later application/data adapter can replace the fixture while preserving the view-data contract.
