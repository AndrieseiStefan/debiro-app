# Documents (E1-011)

The global authenticated Documents page is available at `/documents` and `/en/documents`, with **Documente** active in the shared app shell. It follows [canonical mockup 11](../design/mockups/11-documents.png) using `AuthenticatedPageHeader`, summary cards, all/review tabs, shared search and filter controls, upload-date sort, document table, status badges, and eight-row pagination. Its 24 typed, deterministic summary fixtures explicitly associate every document with `vendorId` and `vendorName`; ownership is never inferred from AI-extracted text. The mockup's demo totals and dates are sample data, so visible counts derive from these fixtures instead. The fixed fixture statuses are presentation snapshot values, not live compliance calculations.

All controls are browser-local. Search covers localized document name, filename, vendor, and type. Vendor, type, status, and upload-year filters combine with the current tab; changing a criterion resets pagination to page one. Filter reset clears filters without changing search or tab, while filtered-empty recovery clears all criteria. The no-documents state is separate from the filtered-empty state. The route has no asynchronous data source, so it has no loading or remote-error state. No upload, backend pagination, document API, storage, authorization, or authoritative verification is implemented.

The [Add Document flow](add-document.md) prepends browser-memory records to these fixtures. New manual uploads use a separate **Uploaded** status; the status filter appears only when such a record exists, preserving the fixture-only mockup. Summary counts and filters include local records without changing the fixture statuses. `construct-pro-tax-2024` remains the sole *fixture* with an implemented review route; exact-match locally simulated documents also have their own review routes. Other row action affordances are explicitly unavailable in the demo rather than linking to deterministic 404s. Review's breadcrumb and “Înapoi la documente” return to this page. E1-027A moves the existing vendor/type/status/upload-year fields into the shared `FilterPanel`, closed initially rather than permanently occupying a side column. Its anchored desktop popover and shared mobile Drawer, active count (excluding query), immediate filters and query-preserving Reset follow the [shared contract](../design/ui-foundation.md#authenticated-search-and-filters-e1-027a). Sort stays outside the panel. The table scrolls inside its own region at reduced widths without document-level horizontal overflow. English copy is a translation awaiting product-owner review. No screenshot baselines were approved or committed.

E1-027 extends type filters for ISO, work permits and company-custom uploads, filters local documents by the active company, and removes associated documents from this projection after confirmed VendorRequirement deletion. Seeded associated document IDs are suppressed in memory, not deleted from fixture source files. This does not add general document deletion/renewal or change review outcomes.
