# Documents (E1-011)

The global authenticated Documents page is available at `/documents` and `/en/documents`, with **Documente** active in the shared app shell. It follows [canonical mockup 11](../design/mockups/11-documents.png) using `AuthenticatedPageHeader`, summary cards, all/review tabs, shared search and filter controls, upload-date sort, document table, status badges, and eight-row pagination. Its 24 typed, deterministic summary fixtures explicitly associate every document with `vendorId` and `vendorName`; ownership is never inferred from AI-extracted text. The mockup's demo totals and dates are sample data, so visible counts derive from these fixtures instead. The fixtures initialize shared uploaded-document domain records; pending/approved/rejected review outcomes are no longer page-specific overrides.

All controls are browser-local. Search covers localized document name, filename, vendor, and type. Vendor, type, status, and upload-year filters combine with the current tab; changing a criterion resets pagination to page one. Filter reset clears filters without changing search or tab, while filtered-empty recovery clears all criteria. The no-documents state is separate from the filtered-empty state. The route has no asynchronous data source, so it has no loading or remote-error state. No upload, backend pagination, document API, storage, authorization, or authoritative verification is implemented.

The [Add Document flow](add-document.md) prepends browser-memory uploads to this same source. Every new upload is pending with internal Needs Review, not a fifth Uploaded compliance state. Approval persists confirmed metadata and derives Valid/Expiring Soon/Expired; rejection retains history but removes the record from active rows/counts. Total/Needs Review/Valid/Expiring Soon summaries, filters and review tabs all derive from the active company-owned dataset. All pending fixture/local records expose their own Review route; only `construct-pro-tax-2024` has the code-native A4 sample viewer. Other reviews show an honest metadata-only preview. Approved/non-review row actions remain unavailable pending the document-management design. Review's breadcrumb and “Înapoi la documente” return to this page. E1-027A moves the existing vendor/type/status/upload-year fields into the shared `FilterPanel`, closed initially rather than permanently occupying a side column. Its anchored desktop popover and shared mobile Drawer, active count (excluding query), immediate filters and query-preserving Reset follow the [shared contract](../design/ui-foundation.md#authenticated-search-and-filters-e1-027a). Sort stays outside the panel. The table scrolls inside its own region at reduced widths without document-level horizontal overflow. English copy is a translation awaiting product-owner review. No screenshot baselines were approved or committed.

E1-027 extends type filters for ISO, work permits and company-custom uploads, filters local documents by the active company, and removes associated documents from this projection after confirmed VendorRequirement deletion. Seeded associated document IDs are suppressed in memory, not deleted from fixture source files. This does not add general document deletion/renewal. E1-028 changes review outcomes through the same records, preserving rejected history outside current projections.
