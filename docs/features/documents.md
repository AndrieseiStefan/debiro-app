# Documents (E1-011)

The global authenticated Documents page is available at `/documents` and `/en/documents`, with **Documente** active in the shared app shell. It follows [canonical mockup 11](../design/mockups/11-documents.png) using `AuthenticatedPageHeader`, summary cards, all/review tabs, search, an optional filter panel, upload-date sort, document table, status badges, and eight-row pagination. Its 24 typed, deterministic summary fixtures explicitly associate every document with `vendorId` and `vendorName`; ownership is never inferred from AI-extracted text. The mockup's demo totals and dates are sample data, so visible counts derive from these fixtures instead. The fixed fixture statuses are presentation snapshot values, not live compliance calculations.

All controls are browser-local. Search covers localized document name, filename, vendor, and type. Vendor, type, status, and upload-year filters combine with the current tab; changing a criterion resets pagination to page one. Filter reset clears filters without changing search or tab, while filtered-empty recovery clears all criteria. The no-documents state is separate from the filtered-empty state. The route has no asynchronous data source, so it has no loading or remote-error state. No upload, backend pagination, document API, storage, authorization, or authoritative verification is implemented.

Only `construct-pro-tax-2024` has an implemented review fixture, so only that row links to `/documents/construct-pro-tax-2024/review` (and its English route). Other row action affordances are explicitly unavailable in the demo rather than linking to deterministic 404s. Review's breadcrumb and “Înapoi la documente” now return to this page. At reduced widths, the filter panel stacks and the table scrolls inside its own region without document-level horizontal overflow. English copy is a translation awaiting product-owner review. No screenshot baselines were approved or committed.
