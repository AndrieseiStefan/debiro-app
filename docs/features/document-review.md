# Document Review (E1-009)

E1-027 confirmed uploaded-requirement deletion suppresses the associated local/seeded Review view for the current browser-memory session; stale client Back/links show the existing document-unavailable recovery. It does not change Review validation or outcome semantics.

The authenticated review screen belongs to the Documents domain at `/documents/[documentId]/review` and `/en/documents/[documentId]/review`. It reuses `AuthenticatedAppShell`, with **Documente** active. The deterministic `construct-pro-tax-2024` fixture resolves, as do [browser-local Add Document records](add-document.md) marked for review. Unknown non-local IDs return 404; a local ID lost after refresh shows a return-to-Documents recovery state. The breadcrumb is **Dashboard > Documente > Revizuiește documentul**. The document's vendor association is data context, not a vendor-based route hierarchy. The Documente breadcrumb and “Înapoi la documente” link return to the global [Documents page](documents.md) at `/documents` or `/en/documents`. The Documents sidebar item also links there.

The implementation follows [canonical mockup 09](../design/mockups/09-document-review.png): context, heading, extraction callout, document viewer, AI-extracted fields, confidence estimate, edit callout, and reject/draft/confirm controls. The mockup's vendor name and document filename are sample data and use the existing Construct Pro fixture instead. The mockup's active **Furnizori** sidebar item is intentionally changed to **Documente** as required by E1-009. The page-specific breadcrumb/back row, eyebrow, and review callout are composed locally because this structure does not fit the simpler shared authenticated page header without altering its established consumers. The viewer renders a deterministic code-native A4-proportioned sample page rather than using the mockup raster or a real stored PDF. Its intrinsic page dimensions stay fixed; fitting and zoom use one uniform scale, and excess size scrolls inside the viewer. The header and two main panels stack before their minimum usable widths collide. The three actions reflow from one row to two rows and then a vertical stack based on panel width, keeping each helper under its action.

The typed fixture contains document identity, vendor context, filename and size, upload metadata, extraction confidence, and original extracted values. The form copies those values into browser-local state. Required fields and `DD.MM.YYYY` dates are validated on confirmation, including expiry chronology. Draft and rejection are immediate local states and do not send data anywhere. Confirmation records only a local human-confirmed state and announces that nothing was saved to a server. Edits after an action return the form to an unsaved local state; reload restores the fixture. The original extracted values remain unchanged in the fixture and the sample preview.

**Extracted** means machine-detected data; the fixture's 94% confidence is an estimated extraction accuracy, not proof of correctness. Local simulated review uses the new document's identity and data, hides the AI confidence display, and shows a filename-only placeholder because file bytes are not stored. Its wording explicitly distinguishes fixture-prefilled metadata from actual file extraction. **Confirmed** means a human accepted or corrected the fields. **Verified** would require an independent authoritative-source check, which is not implemented. The mockup's action helper “Document validat” is retained as locked visible copy, but the resulting state explicitly says human-confirmed, not authoritatively verified. No OCR, AI call, remote upload, private storage, signed URL, persistence, compliance recalculation, or audit backend exists. Future integration must place authorization and private document access at the server boundary, process the stored file, retain extracted-versus-corrected provenance, persist a reviewer action with audit metadata, and reserve verified status for an independent check. English wording is a translation awaiting product-owner review.
