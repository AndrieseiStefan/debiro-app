# Dashboard overview (E1-003)

The directly accessible `/dashboard` and `/en/dashboard` routes implement the authenticated-looking overview from [mockup 03](../design/mockups/03-dashboard-overview.png) for the default Demo Company workspace. This is a fixture-backed E1 screen, not a signed-in product flow. Every active company keeps this destination and its normal layout; empty workspaces have zero-derived cards, empty panels and an Add your first vendor setup entry through the existing Add Vendor drawer.

`DashboardPage` receives a typed `DashboardViewModel` from `src/features/dashboard/fixtures.ts`. The fixture supplies greeting/presentation metadata, not independent operational totals. Current vendor metrics/percentages, accepted expiry/missing rows and recent owned audit events derive from the shared [E1 records and timeline](../project/fixture-data.md). This remains browser-memory demo data, not persisted or authoritative compliance. The Romanian mockup labels are retained with `ComplyHub` replaced by text-only `DEBIRO`; `/en/dashboard` has parallel English copy awaiting product-owner review.

The screen introduces `AuthenticatedAppShell` with its own `AppSidebar` and `AppTopBar`. Its welcome area composes the shared `AuthenticatedPageHeader`, supplying an eyebrow and compliance callout without a primary action. It reuses low-level `AppShell`, `Button`, `Surface`, `StatusBadge`, `BrandWordmark`, locale routing, and tokens, but never the public/pre-auth header or the Landing marketing dashboard preview. Visible areas are the welcome area, four summary cards, attention-documents table, native CSS supplier-status donut and legend, recent activity, and closing illustration banner.

Search accepts local typing and locale links switch routes. Furnizori, Documente, Cerințe, and Notificări link to their implemented fixture-backed destinations; vendor creation remains available from Furnizori and, only for an empty company, Dashboard's first-vendor setup action. The shared shell provides a fixture-backed [bell notification panel](notifications-audit.md) and [profile menu](profile-dropdown.md). Other unimplemented navigation and actions remain safely inactive. There are no `#` destinations, real global search, authentication/session guard, API, database, or provider integration. The page has no remote loading/error state.

The authenticated shell uses the full available viewport width, not the public 1350px centered page shell. On desktop its 260px sidebar stays pinned to the viewport; the brand and organization card remain visible while the Dashboard page scrolls, and navigation scrolls internally on short viewports. The 72px app top bar stays part of this separate shell. At its local 800px collision point, the sidebar becomes a dark app header containing brand, notification/locale/profile utilities, separate compact organization context, and horizontally scrollable navigation. A single light search row follows it. KPI cards reserve separate icon, flexible text, and chevron columns; titles and secondary labels wrap within each card, and the grid reduces columns before card content collides. The documents table scrolls inside its panel where necessary and keeps the full “Expiră curând” badge visible. The supplier-status legend uses “Lipsesc documente” for missing documents. The page itself does not scroll horizontally at tested 1024, 375, or 320px widths. A designed mobile navigation pattern remains a later product decision.

Dashboard layout must remain equivalent on direct load and after client-side navigation through Vendors, including its card and panel geometry.

E1-032Ba makes the four vendor KPI cards whole-card locale-preserving links using the existing SummaryMetricCard/Surface treatment. Total enters `/vendors` without a compliance filter; the other cards enter `?status=compliant`, `attention` or `noncompliant`, initializing the existing Vendors filter. Zero counts remain navigable to the filtered empty result. Native link keyboard/modifier behavior, shared hover/focus treatment and the visual chevrons are retained; no nested action or new Dashboard destination is introduced.

The bottom mountain artwork is a generated transparent illustration, not a mockup screenshot; its exact painting and the text-only brand differ from the raster reference. The canonical mockup is unchanged, and generated visual captures remain ignored, unapproved comparison artifacts.

E1-031 scopes all projections to the active company before counts/filters and derives monthly helper values from owned events. Populated Dashboard does not regain a general Add Vendor CTA. See [workspace ownership and onboarding setup](company-workspaces.md).
