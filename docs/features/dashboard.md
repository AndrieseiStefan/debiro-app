# Company-wide Dashboard (E1C-007A–A3)

`/dashboard` and `/en/dashboard` implement [the approved redesign](../design/mockups/dashboard-redesign.png). The existing authenticated shell, company switcher, search, bell, profile menu, locale-aware routing and shared PageHeader remain unchanged. E1C-007A3 replaces only the header's title/supporting copy with the session-stable personalized greeting below; the approved generic DEBIRO greeting/company-overview description remain the neutral SSR/error fallback. There is no duplicate company selector/date picker, general Add Vendor CTA, old compliance callout or mountain banner. The Landing miniature Dashboard is unchanged.

## Presentation-only greeting sessions (E1C-007A3)

The existing global `useUserProfile` provides the live first name, preserving spelling and multi-word first names. Empty first names fall back to the first nonempty display/full-name token; missing names use each variant's localized unnamed form. Missing identity or translation uses the established neutral title/subtitle. Names are never copied into greeting storage. Existing E1 profile edits still have their tab-memory lifetime: refresh restores the profile fixture, not a name snapshot persisted by Dashboard.

`greetings.ts` defines 24 stable identifiers: 18 unrestricted and two each for morning (05:00–11:59), afternoon (12:00–17:59) and evening (18:00–04:59). All titles/subtitles, including unnamed forms, come from the RO/EN next-intl catalogs. Deterministic rotation skips the previous variant, the current tab variant and ineligible dayparts; only new selection reads the browser's local hour. A saved greeting does not change when the clock enters another daypart. Copy is encouragement, not a claim of real activity or compliance.

`greeting-session.ts` reuses `browserSession` for module-reinitialization-safe memory and stores only `{version: 1, userId, selectionId, variantId}` under `sessionStorage['debiro.dashboard-greeting.v1']`. The opaque selection ID distinguishes an opener-copied tab selection; it is **not an authenticated session ID/token** and grants no access. A newly opened same-origin tab selects independently even if the browser copies its opener's sessionStorage. Refresh/direct navigation with an existing selection, client remounts, company changes and locale changes preserve that tab's selection. The last variant ID per user is the only greeting value kept in localStorage, for immediate-repeat avoidance across tabs. Other session/business stores are never cleared, serialized or changed.

The accepted E1 contract preserves demo authentication: a valid existing Login submission calls `beginDashboardGreetingSession(readUserProfile().userId)` immediately before the unchanged Dashboard navigation. Submitted credentials/email do not establish or change identity and are never passed to greeting storage. Invalid submission does not rotate. Direct Dashboard entry selects only if the current tab/user lacks a valid selection. `useSyncExternalStore` has a null server snapshot; client resolution runs after hydration, so server and hydration markup use the same localized neutral fallback. Existing PageHeader typography/layout remain; a Dashboard-local word-wrap guard contains unbroken profile names without changing shared typography or other pages.

**E2 integration deferred:** Login remains a local navigation demo; Logout remains unavailable. No provider, auth/session cookie, account-switch UI, route, API or database entity is added. The presentation-only `beginDashboardGreetingSession(userId)` and `endDashboardGreetingSession(userId)` hooks are ready for future real sign-in/account entry and explicit logout. They do not authenticate/sign out users. Hook/account-isolation tests exercise this seam; real logout/account-switch integration and end-to-end authentication validation are explicitly deferred until E2.

Malformed/unknown stored variants are rejected safely. Blocked storage/getters/quota errors use the same in-memory selection without crashing or fake loading. When sessionStorage is unavailable, refresh durability cannot be guaranteed; when persistent history is unavailable, cross-tab repeat avoidance cannot be guaranteed. Current-tab rotation remains deterministic, and sessionStorage alone still preserves refresh/new-Login behavior when only localStorage is blocked. Existing business-data reload semantics are unchanged.

## Presentation and reuse

Three linked `SummaryMetricCard` overview variants lead to Vendors, Company Documents and Employees. This opt-in variant composes the same Surface, AppIcon, native locale-aware link and focus/hover treatment; existing Dashboard/Documents/directory variants retain their geometry. The optional overview detail uses secondary caption text for the employee active/inactive breakdown. Vendor/Company secondary counts retain their existing definitions; Employee categories use the exact active tracking distribution below.

Desktop has three domain panels and two lower previews. At the existing 1199px boundary, the domain grid uses two columns with Employees spanning the row; below 768px it stacks. Activity and expirations use one column on reduced widths. A local container query wraps row metadata when a panel has at most 300px of content width, including narrow desktop columns, without squeezing names, hiding text or adding nested table scrolling. Existing Surface, SectionAction, Avatar, EmptyState/ErrorState, VendorComplianceBadge and document StatusBadge conventions are reused. Every preview is capped at five, without pagination or internal vertical scrolling.

The existing native CSS Vendor donut is retained through a minimal presentation-only `DashboardStatusChart`, also used by Employees. Counts, colors, legend and empty-ring geometry remain shared; no chart library or domain calculations are introduced. Vendor counts come from the same projection as the directory. Inactive vendors remain included in Total but excluded from active compliance counts; their remaining donut segment is neutral and explicitly labeled Inactive, never silently colored Noncompliant. The missing-requirement pseudo-category is not another Vendor compliance status.

The Company Documents panel adds the active company display name as muted secondary text below its unchanged heading. It reads the existing company context on every render; no selector, duplicate name state or navigation contract is introduced. Its page heading and the sidebar's parent Company disclosure show the same identity. The sidebar name stays visible when collapsed, with ellipsis and a full accessible description/native title; Company Documents and Employees children keep their regular labels only. Missing names are omitted, and long names wrap in headings rather than widening the page.

## Read-only data contracts

`workspace-overview.ts` composes existing company-scoped selectors; it creates no store, entity, event, API, migration, dependency or status model. Vendor rows reuse `projectVendorDocuments`, `getVendorRequirements`, `vendorSummary` through the existing Dashboard projection. The directory's zero-requirement Compliant rule and active/inactive definitions are preserved. Attention vendors are ordered by existing severity, next document deadline, localized name and ID. Their file ratio is the existing informational directory ratio, never the source of compliance.

Company Documents uses `companyDocumentList`, `companyDocumentMetrics` and existing status sorting. Total counts current uploaded versions, while Attention also includes missing required requirements; optional missing rows are excluded. Expiring Soon is a labeled overlapping subset, not an independent exclusive category. Historic/rejected/superseded versions do not become listing rows. Document rows open the existing authorized CompanyDocumentManager in the exact requirement context, including missing requirements; legacy unbound rows use their existing Company Documents destination. No new query-parameter/deep-link protocol or details implementation is introduced.

Employees uses `employeeWorkspace`, `projectEmployeeDocuments`, `employeeDocumentMetrics` and `employeeListDocumentMetrics` exactly as the directory. The top-level Total KPI includes inactive employees, with a subtle active/inactive breakdown whose sum equals Total. Both the KPI and chart reuse the same authorized active-employee distribution and presentation labels: Complete (green), Attention (amber), Not Configured (neutral). These counts sum to the active total; expiring-document counts are not substituted for employee tracking counts. Romanian Complete is presented as `În regulă` in both Dashboard displays; the existing `complete` tracking status and directory terminology remain unchanged. Attention is required-document based, never review based. Zero requirements remain Not Configured; optional missing requirements do not create Attention. Inactive employees never enter these categories; zero active employees has a neutral empty ring and no misleading percentages.

Only active employees whose existing tracking projection is Attention enter the five-item preview. Presentation urgency orders required expired, missing, then expiring-soon issues, followed by the earliest date within that issue category, localized employee name and stable ID. A person appears once; the concise issue count uses already-projected required rows, not a new expiry threshold or tracking rule. Entries retain initials, name, job title, tracking badge and existing Employee Details navigation. Complete and Not Configured employees never fill empty preview slots. No qualifying people produces the compact approved RO/EN no-attention message; no active people produces the existing empty ring, and all Not Configured people produce a neutral ring. Existing first-vendor setup remains available inside the empty Vendors panel only to authorized company Administrators.

## Activity coverage and navigation

Recent Activity merges existing company-filtered Vendor audit records (`companyAuditEvents`, fixture and actual local audit records) with authorized `getEmployeeActivity` records. Original source IDs, actors, localized actions, actual timestamps and date-only provenance are preserved. IDs are namespaced/deduplicated; newest timestamp and stable ID determine the five-item preview. Seeded reminder-delivery claims are excluded because E1 delivery is unavailable. No new events are recorded, and metadata is never turned into invented historical activity.

Available Vendor/document contexts use existing Details/Review/History routes and permissions. Employee events use the owned Employee Details route. Events whose original entities no longer exist remain readable without broken navigation. The existing Notifications audit anchor (`/notifications#audit-title`) is used by View All Activity.

Current gap: Company Document lifecycle operations do not record audit events. This task does not synthesize them or change recording logic. Employee activity is recorded separately and is not yet present in Notifications. Notifications' domain extension and complete activity coverage belong to E1C-007B; its layout/filters/exports are unchanged here. Global Search remains unchanged and its additional-domain coverage belongs to E1C-007C.

## Upcoming expirations

Vendor expirations reuse `notificationDocuments`; Company and Employee entries reuse validated current listing rows. The existing `approvedCompliance` utility and configured requirement warning intervals determine Company date eligibility independently of review state (so a pending-review Company file can still have an upcoming date). Employee effective statuses already provide the no-review expiry projection. `calendarDaysUntil` and `localizedDate` retain the shared deterministic E1 clock and localization. No new hardcoded warning window is introduced.

Only current, non-rejected/non-superseded versions with genuinely upcoming dates are included; expired/manual-expired records are excluded. Employee expirations preserve active-only metrics and private access. Entries are ordered by actual expiry then stable domain/entity identity and capped at five. Vendor files use their existing Vendor/document destination; Company entries open the same Company manager; Employee files use their existing owning Details page because no document-specific Employee deep link exists. View All uses `/notifications#expiring-section`, not a misleading Vendor Documents-only destination. Notifications currently covers Vendor expirations only; unified coverage remains an explicit E1C-007B gap.

## Authorization, isolation and recovery

Existing active membership/document access gates Vendor/Company data. Employee document workspaces, private metric calculations, activity and expirations are read only after the existing Administrator personnel check. Restricted employee panels show the established restriction and directory link, never a private chart, attention rows, inferred zeros or hidden tooltip/DOM metadata. Basic directory access remains unchanged. Company switches recompute all inputs and unmount scoped document UI; no previous-company data is retained on Dashboard. No sessions are reset or rewritten.

Malformed Company/Employee data uses local existing error states without crashing other domains. Vendor projection failures are isolated likewise. Invalid event dates are ignored; missing entities have no broken action. Empty companies retain all five panels and truthful zero/empty states. No artificial loading or random/current-clock display values are introduced during render. E1 browser checks are not production server authorization.
