# Vendor Details (E1-005)

The dynamic `/vendors/[vendorId]` and `/en/vendors/[vendorId]` routes implement [canonical mockup 05](../design/mockups/05-vendor-details.png) for the deterministic `construct-pro` fixture. E1-026A resolves all 24 listed fixture identities and [locally created vendors](add-vendor.md) through the same `VendorDetailsPage` and typed view model. Unknown non-local IDs return Next.js 404; a local ID lost after refresh shows a return-to-Vendors recovery state. Fixture dates, names, contact values, and counts are static mockup-style samples, not live compliance results or a domain schema.

`VendorDetailsPage` reuses `AuthenticatedAppShell` and `AuthenticatedPageHeader`. The Vendors navigation remains active. The page includes the vendor breadcrumb, identity and registration metadata, compliance summary, invitation/add-document actions, five contact fields, four visible section tabs, the five-row document/status table, missing-document notice, and closing mountain banner. Romanian visible labels and descriptions follow the mockup; English localization preserves their meaning pending review. The canonical image is unchanged.

The E1-005A responsive composition keeps the shared page header unchanged while arranging its vendor identity, the status card, and the existing actions in a feature-owned grid. The company icon stays beside the name as the identity moves between rows; CUI, registration, and an intrinsically sized category badge stay with it. The status/actions move below identity before intermediate-width collision, then occupy separate rows with stacked buttons in the reduced authenticated layout. Contact items retain their mockup order and flow through a balanced three-column, two-column, or single-column layout as space decreases; remaining items expand to fill their row, with separators following cell boundaries.

Breadcrumbs, Vendors List names and the context-menu Open Supplier action navigate client-side. Document search filters fixture and [locally created document rows](add-document.md). The Construct Pro invitation action opens the [E1-007 Invite Vendor drawer](invite-vendor.md) over this same page; it remains a local preview with no real email or token. `Adaugă document` opens the shared Add Document drawer for fixture and locally created vendors. The Contacts and Activity tabs, filter, missing-document upload action, most document-row actions, and applicable-requirements action remain visibly present but inactive; a locally created review-required row links to its matching Review screen. Notes is active when the vendor record has a saved note, including edited seeded vendors. The document table scrolls within a focusable region at narrow widths; no page-level horizontal overflow is intended. Generated visual captures are ignored comparison artifacts, not approved baselines.

Other seeded Details views initially reuse only known identity, category, CUI and optional contact name from the list. Absent contact fields are omitted (an entirely absent contact block shows a safe empty message); documents and notes are not invented. Their existing compliance snapshot is retained, while unavailable document-level evidence is explicitly identified instead of fabricating a valid-document count or requirements. The list's aggregate fixture document counts may therefore exist without corresponding document-row fixtures. A neutral Inactive badge near identity reads the shared vendor lifecycle state and never disables Details or editing, or changes compliance. Reactivation preserves the same data.

E1-026B adds the secondary `Editează furnizor` action before Invite and the primary Add Document action. The header moves status/actions below identity before the three controls crowd the title; actions wrap within their region and retain the existing mobile stacking. Edit reuses the Add Vendor form and shared Drawer. All eleven metadata fields prefill from known values; absent values remain empty, including missing required fixture email, which must be provided before Save. The canonical Romanian fixture address supplies the locale-independent draft; unchanged fixture address translations are preserved, while an edited address is business data shown verbatim in either locale.

The draft is separate from committed state. Save is enabled only for valid, normalized changes and publishes one atomic update to the existing browser-memory vendor store by stable ID. Details, contact fields, Notes and list search/filter/sort update without refresh; the route, lifecycle, compliance snapshot, expiry, documents and invitation preview stay associated with the same identity. Save closes the drawer and announces `Furnizor actualizat`. Cancel/X/Escape/backdrop close a clean draft immediately; dirty close reuses the Requirements unsaved-changes confirmation with Continue Editing/Discard. The shared confirmation makes the underlying drawer inert and owns keyboard focus; backdrop mousedown prevents stealing its initial focus. Discard does not save. No empty edit drawer is offered for missing vendors.

Seeded vendors belong to the Demo company; local records carry their creating company ID. CUI uniqueness is checked within that company, excluding the edited ID. Existing alternate-company operational-workspace recovery remains unchanged; this is not a new workspace implementation. Category and descriptive industry remain separate; category changes do not assign/remove templates. Edits survive client navigation and locale switches, not refresh. No backend, persistence, permissions or new invitation/lifecycle behavior is added.

Created vendors display only submitted optional contact/registration data and any submitted note, initially with an empty document table and a setup-needed summary instead of a compliance claim. Local document creation may populate that table without fabricating valid status or compliance. Their invitation preview is unavailable: no demo link or invitation is fabricated. The fixture can later be replaced by a real application/API provider without changing the screen contract. This task adds no authentication, backend, persistence, remote upload, invitation sending, compliance calculation, or provider integration. The banner mountain treatment reuses existing approximate artwork where no exact source asset exists.
