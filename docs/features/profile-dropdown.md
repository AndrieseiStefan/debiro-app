# Profile Dropdown (E1-020)

The authenticated shell opens a global-user profile dropdown from its existing avatar control on desktop and compact layouts. It follows [canonical mockup 20](../design/mockups/20-profile-dropdown-menu.png), except the obsolete **Membri companie**, **Invită utilizator**, and **Administrare companie** group is omitted. Those active-company actions belong under **Setări companie**. English copy awaits product-owner review.

The header reads name, email, and initials from the existing current-user fixture. It resolves the displayed role from the current user's membership in the [active company](my-companies.md); the role is not a global user property. The active company's name and **Companiile mele** badge derive from the same shared accessible-company source (two initially, increasing after local creation), not the mockup's sample count. There is no received-invitations source, so **Invitațiile mele** has no badge; pending company-member invitations are a different concept.

The five rows are **Profilul meu**, **Companiile mele**, **Invitațiile mele**, **Centrul de ajutor**, and **Logout**. **Companiile mele** links to the implemented RO/EN page and closes the menu. The other destinations, help URL, and real logout are not implemented, so they remain focusable, semantically unavailable demo controls without fake navigation or session mutation. The menu toggles from the trigger, closes on outside pointer interaction or Escape, and gives focus back to the trigger on Escape. One shared open state prevents desktop and compact instances from being open simultaneously. It is a viewport-contained, non-modal dialog with no change to authenticated header geometry. No auth provider, backend, or visual screenshot baseline was added.
