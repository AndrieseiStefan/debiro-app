# Profile Dropdown (E1-020)

The authenticated shell opens a global-user profile dropdown from its existing avatar control on desktop and compact layouts. It follows [canonical mockup 20](../design/mockups/20-profile-dropdown-menu.png), except the obsolete **Membri companie**, **Invită utilizator**, and **Administrare companie** group is omitted. Those active-company actions belong under **Setări companie**. English copy awaits product-owner review.

The header reads name, email, initials, and accessible-company count from the existing company-settings current-user fixture. It resolves the displayed role from the current user's active membership in the active company; the role is not a global user property. The active company's name comes from that same fixture. The **Companiile mele** badge uses its shared accessible-company count (two in the current demo), not the mockup's sample count. There is no received-invitations source, so **Invitațiile mele** has no badge; pending company-member invitations are a different concept.

The five rows are **Profilul meu**, **Companiile mele**, **Invitațiile mele**, **Centrul de ajutor**, and **Logout**. Their destinations, help URL, and real logout are not implemented, so they are focusable, semantically unavailable demo controls without fake navigation or session mutation. The menu toggles from the trigger, closes on outside pointer interaction or Escape, and gives focus back to the trigger on Escape. One shared open state prevents desktop and compact instances from being open simultaneously. It is a viewport-contained, non-modal dialog with no change to authenticated header geometry. No auth provider, backend, company switcher, or visual screenshot baseline was added.
