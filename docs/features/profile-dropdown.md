# Profile Dropdown (E1-020)

The authenticated shell opens a global-user profile dropdown from its existing avatar control on desktop and compact layouts. It follows [canonical mockup 20](../design/mockups/20-profile-dropdown-menu.png), except the obsolete **Membri companie**, **Invită utilizator**, and **Administrare companie** group is omitted. Those active-company actions belong under **Setări companie**. English copy awaits product-owner review.

E1-032A2 replaces the separated avatar/chevron trigger with a circular control (38px desktop, 34px compact), reusing the shared initials avatar. A small chevron badge is attached at its bottom-right in both shell modes; no elongated container or separate chevron width remains. Circular hover/pressed states and a visible focus ring preserve the existing button semantics. Menu contents, placement, overlay handling and header utility gaps are unchanged.

The header reads live name, email and initials from the [global-user profile](my-profile-invitations.md). It resolves role from the current user's membership in the [active company](my-companies.md), never as a global user property. The company name and **Companiile mele** badge derive from shared accessible-company state (two initially, increasing after creation or accepted access). **Invitațiile mele** counts only current-user pending, unexpired received invitations and hides at zero; company-owned outgoing member invitations are a distinct source.

The five rows remain **Profilul meu**, **Companiile mele**, **Invitațiile mele**, **Centrul de ajutor**, and **Logout**. The first three use locale-preserving client links to `/profile`, `/profile/companies` and `/invitations`, close on navigation and highlight the exact active route using existing row styling. Help and real logout remain focusable, semantically unavailable demo controls without fake navigation/session mutation. The menu toggles from the trigger, closes on outside pointer interaction or Escape, and restores trigger focus on Escape. One shared open state prevents desktop/compact panels opening simultaneously. The viewport-contained non-modal panel, original layout and authenticated header geometry are preserved. No auth provider, backend or approved screenshot baseline was added.
