# Document Requirements (E1-006, E1-023, E1-025A)

`/requirements` and `/en/requirements` use [canonical mockup 06](../design/mockups/06-document-requirements.png) for the authenticated template workspace and [23A](../design/mockups/23A-Add-suggested-document-to-template.png) / [23B](../design/mockups/23B-Add-personalized-document-to-template.png) for the Add Document drawer. The top-level breadcrumb is **Dashboard > Cerințe**. The visible brand is plain uppercase `DEBIRO`.

The page reuses the authenticated shell, page header, breadcrumbs, shared Drawer, Button, and Surface. Existing Demo Company templates begin from deterministic fixtures; template search and selection are browser-local. An existing template uses one company-scoped working copy for its name, description, vendor category, document additions/removals, required/optional rules, expiry alerts, validity, and custom-document name/description/issuer. Save validates and commits the complete working copy; Cancel discards it. The template list continues to show committed metadata and counts until Save. The Documents tab is active; Preview and template duplication/deletion remain inactive. There is no Settings and applicability tab.

`Șablon nou` and `Adaugă șablon nou` switch the existing right workspace into a new-template draft. A new template requires a unique normalized name within the active company, exactly one required `Categorie furnizor` from the same operational category IDs used by Add Vendor, and at least one document. Seeded templates also have one category ID; the legacy maintenance and consulting examples use the construction category for MVP. A vendor has one operational category, while its optional industry is descriptive and does not affect template eligibility. Matching category IDs determine eligibility, but automatic assignment is not implemented. Multiple template categories, country, project/location, supplier/subcontractor rules, and conditional applicability are deferred. The draft starts with an explicit zero-document state. Saving creates a company-scoped browser-memory template and selects it; canceling discards it. A dirty draft asks for confirmation before cancellation, template selection, sidebar navigation, or workspace switching. A direct page reload is protected by the browser's standard unsaved-changes prompt; browser-memory data does not persist across reloads.

The Add Document drawer supports local catalog search and a custom-document mode. Catalog entries have stable IDs and read-only localized names; a template document stores its catalog ID **or** its custom name, never both. Required status, expiry warning, and validity belong to each template document, not to the shared catalog. Custom names are trimmed and checked against template duplicates with case-, whitespace-, and accent-insensitive normalization; descriptions are limited to 200 characters. Existing-template edits use the same name uniqueness and shared vendor-category validation as creation, excluding the template's own name from duplicate detection. A dirty existing-template edit asks for confirmation before template selection, new-template creation, sidebar navigation, or company switching. The simulated global catalog-candidate list records added or renamed custom documents only after template Save, never during an abandoned draft; it is not a published catalog or service integration.

Templates and documents are isolated by the active browser-memory company. Catalog suggestions may be shared, but company templates are not. Romanian and English interfaces use the same catalog identities and rules. At reduced widths the template list stacks above the editor, the rules table scrolls within its focusable region, and the Drawer stays viewport-contained with internal scrolling. The mockups remain unchanged and generated visual captures are ignored review artifacts, not approved baselines.

There is no backend, API, database, authentication, authorization, assignment, document upload, processing, notification delivery, or durable persistence in this feature.
