# Document Requirements (E1-006)

`/requirements` and `/en/requirements` implement [canonical mockup 06](../design/mockups/06-document-requirements.png) as a fixture-backed authenticated presentation screen. The visible brand follows the approved `DEBIRO` text-only contract. The E1-006 brief explicitly activates the `Cerințe` navigation item, although the source mockup highlights `Documente`; the page retains the mockup's `Documente › Cerințe documente` context.

The page reuses `AuthenticatedAppShell`, `AuthenticatedPageHeader`, authenticated breadcrumbs, `Button`, `Surface`, and the existing sidebar. It shows the page title and compliance callout, six searchable category templates, selected-template heading/actions, three tabs, five document-rule rows for the default construction template, local required/optional toggles and alert/validity selectors, availability notice, and footer actions. Selecting a template and searching the template list only change browser-local presentation state. Cancel resets local rule changes. Settings and preview tabs, template creation/duplication/deletion/saving, adding a rule, and row menus are visible but inactive pending defined workflows. No fake destructive or persisted behavior is implied.

`RequirementsViewModel` and its deterministic fixture are presentation types, not a domain schema. A requirement rule specifies what an uploaded supplier document would need to satisfy; it is not that uploaded document. Names, counts, and sample rule values are fixture examples. Romanian mockup labels are transcribed where readable; English conveys the same meaning pending explicit review. The canonical image remains unchanged. At reduced widths the category list stacks and the rules table scrolls inside its own focusable region, while the document itself has no intended horizontal overflow.

There is no backend, API, database, authentication, authorization, assignment logic, upload, document processing, reminder, or provider integration. A later data-source adapter can replace the fixture while preserving the screen view contract. Generated visual captures are ignored review artifacts, not approved baselines.
