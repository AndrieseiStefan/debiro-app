# Document Requirements (E1-006, E1-023, E1-025A/B/C/D)

`/requirements` and `/en/requirements` use [canonical mockup 06](../design/mockups/06-document-requirements.png) for the authenticated template workspace and [23A](../design/mockups/23A-Add-suggested-document-to-template.png) / [23B](../design/mockups/23B-Add-personalized-document-to-template.png) for the Add Document drawer. The top-level breadcrumb is **Dashboard > Cerințe**. The visible brand is plain uppercase `DEBIRO`.

The page reuses the authenticated shell, page header, breadcrumbs, shared Drawer, Button, and Surface. Existing Demo Company templates are editable company-owned copies of deterministic starter fixtures: `starterTemplateId` and version record provenance only, with no live starter sync. Template search and selection are browser-local. An existing template uses one company-scoped working copy for its name, description, vendor category, icon/color, document additions/removals, required/optional rules, expiry alerts, validity, and custom-document name/description/issuer/icon/color. Save validates and commits the complete working copy; Cancel discards it. The template list continues to show committed metadata, appearance, and counts until Save. Documents and Preview are functional, keyboard-accessible tabs. There is no Settings and applicability tab.

`Șablon nou` and `Adaugă șablon nou` switch the existing right workspace into a new-template draft. A new template requires a unique normalized name within the active company, exactly one required `Categorie furnizor` from the same operational category IDs used by Add Vendor, and at least one document. It starts with a generic document icon and blue color; a shared curated icon/color picker also edits existing templates. Seeded templates also have one category ID; the legacy maintenance and consulting examples use the construction category for MVP. A vendor has one operational category, while its optional industry is descriptive and does not affect template eligibility. Matching category IDs determine eligibility, but automatic assignment is not implemented. Multiple template categories, country, project/location, supplier/subcontractor rules, and conditional applicability are deferred. The draft starts with an explicit zero-document state. Saving creates a company-scoped browser-memory template and selects it; canceling discards it. A dirty draft asks for confirmation before cancellation, template selection, sidebar navigation, or workspace switching. A direct page reload is protected by the browser's standard unsaved-changes prompt; browser-memory data does not persist across reloads.

The Add Document drawer supports local catalog search and a custom-document mode. Catalog entries have stable IDs, read-only localized names, and immutable canonical icon/color; a template document stores its catalog ID **or** its custom name, never both. A custom document defaults to the generic document icon and blue, and its appearance can be changed in the drawer or later in the template draft. Required status, expiry warning, and validity belong to each template document, not to the shared catalog. Custom names are trimmed and checked against template duplicates with case-, whitespace-, and accent-insensitive normalization; descriptions are limited to 200 characters. Existing-template edits use the same name uniqueness and shared vendor-category validation as creation, excluding the template's own name from duplicate detection. A dirty existing-template edit asks for confirmation before template selection, new-template creation, sidebar navigation, or company switching. The simulated global catalog-candidate list records added or renamed custom documents only after template Save, never during an abandoned draft; icon/color changes do not create separate candidates. It is not a published catalog or service integration.

The template icon and custom-document icon use the same keyboard-accessible tile with a pencil badge and icon/color popover. In the Add Document custom mode, the icon appears above the document name without a separate appearance heading or text button; catalog suggestions have read-only icons. Duplicate is the sole template header action, while Delete remains in the footer. Duplicate opens an independent new-template draft with a unique `— copie` / `— copy` name, copied metadata, rules, and appearance, and `duplicatedFromTemplateId` provenance. Cancel creates nothing; Save commits only the active company's copy and does not increment or create catalog candidates. Delete requires confirmation, removes only the selected active-company template, and selects a deterministic neighbor or the existing empty state. E1-027 vendor assignment creates independent snapshots, so source-template deletion does not delete vendor requirements, uploads or historical provenance.

Templates and documents are isolated by the active browser-memory company. Catalog suggestions may be shared, but company templates are not. Romanian and English interfaces use the same catalog identities and rules. At reduced widths the template list stacks above the editor, the rules table scrolls within its focusable region, and the Drawer stays viewport-contained with internal scrolling. The mockups remain unchanged and generated visual captures are ignored review artifacts, not approved baselines.

## Supplier-facing Preview (E1-025D)

[previzualizare-cerinte.png](../design/mockups/previzualizare-cerinte.png) governs the Preview section only; the existing surrounding editor remains unchanged. The approved informational banner explains that this is a supplier preview. It shows only the active requesting company and a safe illustrative supplier, never the template name/category, internal issuer, expiry-warning or validity configuration. New and existing unsaved drafts supply the current document names, descriptions, additions/removals, optionality and appearance; switching tabs neither saves nor dirties the template. Zero documents produces a compact no-request state.

`SupplierRequirementContext` and `SupplierRequirementList` are shared with the [Supplier Portal](supplier-upload-portal.md), including document identity/appearance, independent required/optional labels, three status badges, file metadata, and uploaded-only progress. Catalog identity/icon/color resolve through the same `documentDisplay` used by the editor; the catalog holds the new mockups' supplier-facing descriptions separately from the unchanged compact editor descriptions. Custom appearance stays company/template-owned. A catalog-keyed illustrative file fixture supplies uploaded/in-review/missing examples without adding rows or assigning a supplier. Sample statuses and files are not actual supplier compliance. Preview upload buttons are disabled and there are no file inputs, file actions or row-management controls. Template management remains outside the supplier-facing tab content.

The new mockup's all-blue document glyphs are superseded by the task's explicit existing catalog/custom appearance contract. Counts derive from current rules rather than the mockup's sample total. Container queries reflow the shared rows according to the editor's usable width rather than changing the authenticated shell's breakpoints.

E1-027 [vendor template application](vendor-requirements.md) uses committed templates only. Successful Save resolves each custom document to a stable, reusable company-owned document type, using the existing normalized-name rules; drafts/candidate learning remain separate. Renaming a custom document to a different logical name resolves a different type. Catalog IDs and company custom IDs are the assignment identities, never localized labels. Later template edits do not mutate vendor snapshots.

There is no backend, API, database, authentication, authorization, real document upload, processing, notification delivery, or durable persistence in this feature.
