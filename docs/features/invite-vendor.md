# Invite Vendor Drawer (E1-007)

The `Invită furnizor` action on [Vendor Details](vendor-details.md) opens a right-side, viewport-fixed modal drawer modeled on [canonical mockup 07](../design/mockups/07-invite-vendor.png). There is no Invite Vendor route. The E1-007 brief corrects the mockup background: the current Vendor Details page stays behind the dimmed overlay, not Dashboard. The panel enters from the right and closes toward the right; X, Cancel, Escape, and a click on the backdrop close it without changing the route or underlying scroll/context. Focus enters the drawer, stays trapped there while open, and returns to the triggering action on close. The underlying authenticated shell is inert while the drawer is mounted.

The drawer uses the current `VendorDetailsViewModel` vendor name and contact email. The same view fixture supplies a deterministic `debiro.ro/upload/demo-construct-pro` demo URL and fixed reference date for the link-expiry helper. The personalized message, link-validity choice, and two toggles are browser-local. Name/email validation, a 500-character message limit and counter, copy action, and calculated expiry helper are implemented locally. A valid Send Invitation action only reports that the preview is valid and **nothing was sent**. The preview affordance opens the [fixture-backed Supplier Upload Portal](supplier-upload-portal.md) in a new tab; the demo URL is not a real secure token or a usable invitation.

The drawer reuses the existing authenticated page, Button and Field primitives, and icons/tokens. It scrolls internally at short heights and becomes full-width at reduced widths. Romanian visible copy follows the mockup, except placeholder `ComplyHub` branding is replaced with approved `DEBIRO`/`debiro.ro`. English preserves the meaning pending review. The canonical image is unchanged; visual captures are ignored review artifacts, not approved baselines.

No backend, invitation persistence, token generation, email sending, notification delivery, authentication, authorization, or real upload flow is implemented. A future invitation application/API boundary can replace the local preview behavior without changing the Vendor Details entry point.
