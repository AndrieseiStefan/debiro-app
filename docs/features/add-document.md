# Add Document (E1-016)

`Adaugă document` on Vendor Details opens the existing modal right-side [Drawer](add-vendor.md), following [canonical mockup 16](../design/mockups/16-add-document.png). It shares the backdrop, animation, Escape/X/backdrop closing, focus trap and return, scroll lock, and responsive behavior with Invite and Add Vendor. The form and its Cancel/Upload actions scroll together; there is no fixed footer. The mockup's sticky footer is superseded by the explicit E1-016 inline-action requirement.

The upload area accepts drag/drop or a picker for PDF, JPG/JPEG, and PNG up to 10 MB, validating both extension and supplied MIME type. File and document type are required; the vendor name is read-only context. Document number, issue/expiry dates, and issuer are optional. Supplied dates use `DD.MM.YYYY` and must be real dates, with expiry no earlier than issue. No missing metadata is fabricated.

Automatic extraction starts off. Selecting a file alone does not extract anything. The only E1 demo match is the exact `construct-pro` + tax-certificate + `Certificat_fiscal_CP_2024.pdf` combination already represented by the review fixture. Enabling the toggle for that match prefills currently empty metadata from the fixture and sends the new document to Review; the UI explicitly states that the data was *not* read from the selected file. Switching the toggle off, changing file/type, or editing a prefilled field retains manual intent and clears unchanged fixture-only prefill when no longer applicable. Other combinations remain manual even when the toggle is on. There is no OCR or AI call.

Submission creates a browser-memory document associated by `vendorId` and `vendorName`, storing only filename, MIME, byte size, selected type, optional metadata, extraction flags, creation/upload time, and current fixture user. The `File` contents and object URL are not retained. Normal client navigation and locale switching share the record; refresh clears it. Manual documents have an **Uploaded** status, not Valid/Confirmed/Verified; the existing compliance count remains unchanged. An exact-match simulated document has **Needs review** and opens its own `/documents/[documentId]/review` route, not the source fixture's route. The local review shows the new filename/vendor/metadata and a no-content-preview notice; it does not claim to display the uploaded file or actual AI confidence. Review confirmation remains browser-local human confirmation, never authoritative verification or server persistence.

Created rows appear in the vendor's Documents table and increase its displayed row count. The global Documents list, total, filters, and review count derive from the same local records. Fixture documents remain unchanged. Unknown/lost local review IDs show a recovery state rather than unrelated fixture data. No backend, private storage, scanning, processing, AI/OCR, authentication, or compliance calculation is implemented. English copy remains a translation pending product-owner review; generated visual captures are ignored comparison artifacts, not approved baselines.
