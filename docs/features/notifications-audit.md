# Notifications and Audit Activity (E1-010)

The authenticated Notifications page is available at `/notifications` and `/en/notifications`, with **Notificări** active in the shared navigation and a **Dashboard > Notificări** breadcrumb. It follows [canonical mockup 10](../design/mockups/10-audit-activity.png): header and traceability callout, category tabs and date range, three operational summary cards and sections, and a separate audit journal timeline with a local CSV export. The visible `DEBIRO` brand follows the current text-only brand contract. English copy remains subject to product-owner review.

The typed demo snapshot keeps `NotificationActivityItem` (operational activity, including `isUnread`) separate from `AuditEvent` (read-only history with actor and timestamp). Expiring and missing-document summaries are distinct typed presentation records. All dates use the shared [2026 E1 fixture reference](../project/fixture-data.md). Expiring rows derive from accepted current documents; missing rows derive from actual requirements and have no fabricated deadlines. Category tabs filter historical operational notices plus local audit-derived activity rows; these do not create unread/delivered notifications. The date range filters notifications and audit events independently. Summary links expand and focus their sections, and the audit export contains the currently date-filtered audit events in newest-first order. The CSV is generated locally; no reporting service or audit persistence exists.

The authenticated bell opens the compact [canonical notification preview](../design/mockups/17-bell-notification-center.png) on desktop and reduced widths. It takes the six most recent items from the same notification source; its unread badge and the sidebar count derive from `isUnread`. Marking all as read updates browser-memory state shared with the full Notifications page during client navigation. The preview has a localized footer to `/notifications`; only a notification with an existing deterministic review route links directly to that screen. The popover closes on outside interaction or Escape, returns focus to the bell, and stays within the viewport. It has an empty state when the notification source is empty. Read state is not persisted across reloads.

E1-027B adds the shared company-owned browser-memory `LocalAuditEvent` source to the journal and CSV. Successful vendor creation/edit, invitation simulation, template application, upload, review confirmation, lifecycle and requirement removal events use the same AuditEvent concepts and also appear in the owning vendor's Activity tab. Journal and activity periods use the shared fixture reference. Historical notice/audit metadata and date-only uploads share one source with Vendor Activity, without duplicate upload events. E1-028 confirmation/rejection records one company/vendor/document-ID-owned resolution event in this source, reused by Vendor Activity, recent activity, the journal and CSV. There is no separate unresolved-review notification model: current Needs Review rows/counts derive from Global Documents and clear on resolution. Operational notification fixtures remain historical notices, not pending-review flags; bell delivery/read counts remain unchanged. Local audit recording is not notification delivery or durable server audit.

The no-activity state is distinct from a filtered-empty state, which offers a reset action. The page uses synchronous fixtures/local data, so it has no remote loading or error state. It does not deliver notifications, send reminders, offer audit editing/deletion, or persist read/audit state. The browser-local demo has no authentication, backend, database, email, scheduled jobs, or authoritative vendor/document integration. At reduced widths the audit journal stacks below the operational sections, while tabs and tables scroll within their own bounds instead of widening the document.
