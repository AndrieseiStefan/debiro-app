## Current document state

Generic Entity cells identify Vendor, Company or Employee and resolve names from owned records. Expiring Soon includes distinct current `expiring_soon` rows, ordered by expiry, stable domain/entity identity and requirement ID. Pending Company review belongs in attention, not Upcoming Expirations even when its metadata has a near date. Expired/manual-expired, rejected and superseded versions do not enter Upcoming. Existing warning periods and the fixed [E1 fixture clock](../project/fixture-data.md) are unchanged. Required missing obligations only enter Missing; optional missing and Employee Not Configured are not missing obligations. No due dates are invented. Employee expired attention is required-only; optional current-file upcoming dates remain informational for compatibility with the existing Dashboard deadline preview, not Employee tracking or new bell alerts.

Vendor/Company review navigation uses existing role-aware document contexts. Company rows open the existing `CompanyDocumentManager`, with no new query route or review implementation. Missing Company obligations link to Company Documents; Employee rows link to the owned Details route. Employee documents never acquire review tasks. Malformed/unavailable sources fail safely with the existing error/empty patterns, without falling back to another company's data.

## Actual activity and date ranges

Actual activity merges company-owned original audit records with authorized Employee activity. Original source IDs, actors, timestamps, date-only provenance and recorded actions remain unchanged. Read IDs are namespaced (`vendor:`, `company:`, `employee:`), deduplicated by identity, and ordered by occurrence timestamp descending then stable ID. Equal-time distinct operations are not merged by display text. Missing historical entities remain readable with neutral context and no broken destination. Dashboard's first five IDs/order and Notifications Recent/Audit use the same source. Domain timelines retain the same original records, without read-time recording or mirroring Employee events into local audit.

**Accepted activity-clock decision:** date-range reference is the maximum of the existing E1 fixture reference and authorized actual recorded event timestamps in the active company. It applies only to Notifications/Activity/Audit filtering and their relative labels, not document expiration or a new global clock. This admits new real-time Employee operations alongside historical fixture events without rewriting either. Existing Last 7 days / Last 30 days / All options and inclusive cutoffs remain. Current document summaries are current-state snapshots, not historical date-range queries.

**Accepted delivery/demo decision:** seeded sent-reminder notices remain demo notification records only, labeled as such. Their delivery claims are excluded from actual Activity, Audit, Dashboard, Vendor timelines and exported audit. The All/Uploads/Status filters operate on actual recorded activity; Unread/Reminders operate on existing notification records. Consequently these notification-specific counts need not be subsets of the actual All count. The Recent KPI counts authorized actual events in the selected date range, never notice totals or current alerts. No reminder delivery or fabricated send event is added.

The authenticated bell preserves the compact [canonical notification preview](../design/mockups/17-bell-notification-center.png), six-item limit, positioning, localized footer, outside/Escape dismissal and focus restoration. Applicable current Company attention and required Employee missing/expired/expiring alerts reuse this mechanism as read-only **Current state** items, prioritized before historical notices. They have stable requirement/version/status identities, no invented occurrence timestamp and no unread flag; they never enter activity, audit or CSV. Resolution/replacement recomputes the current alert instead of retaining obsolete actionable state. Employee profile/document operations remain Activity/Audit, not newly generated user notifications. Existing Vendor notice behavior and local read activity remain; only authorized deterministic destinations are interactive. Company document alerts open the existing manager and restore focus to the bell.

Bell, sidebar and full-page unread counts still derive solely from existing authorized `isUnread` records. The same company-keyed `readIds` memory and mark-all-read operation survive client/locale/company navigation without a reset or new persistence mechanism. Read state retains its established reload boundary; no backend read acknowledgement or delivery is claimed.

The existing company-owned `LocalAuditEvent` source continues recording successful Vendor actions, document review/lifecycle and member/invitation management. Employee create/edit/template/document mutations reuse their original Employee activity store and real timestamps. No source history is reconstructed from document/version metadata. Company Document lifecycle operations currently have no audit recorder: those operations update current alerts but cannot appear as newly invented activity. This coverage gap, historical backfill and durable audit remain deferred; an explicitly recorded Company event is supported by the read contract.

## Authorization, export and limitations

Membership gates all owned sources; the existing Administrator personnel check runs before reading Employee document/activity metadata, aggregating counts, determining the activity reference, rendering bell/table/timeline context or exporting. Viewer/Reviewer see no private personnel text, IDs or inferred counts. Company switches recompute sources and discard scoped overlays through the existing workspace boundary, not by resetting data/session stores. No file bytes, email addresses or personnel payloads are added to audit projection/logging.

Export remains the local date-filtered newest-first CSV and existing filename/download/escaping behavior. The original nine columns remain in order, followed by `domain,entityId,entityName,requirementId`; original source event IDs, actors and timestamps are retained. Export includes only authorized actual recorded events, not current attention, seeded delivery claims or reconstructed version history. Empty and filtered-empty states remain distinct, with the existing reset action. Synchronous local reads add no fake latency or network retries. Existing mobile table/category scrolling and stacked audit layout remain.

E1 has no authentication, backend, email, worker, durable audit/read state or production authorization. Future E2 must authorize all domain reads/exports server-side using authenticated active-company membership, enforce personnel access before aggregation, retain immutable source event identity/provenance, and record actual operations/delivery transactionally. These are boundary requirements, not new E1 endpoints, event persistence or historical backfill. The Reminder composer still records nothing. Validation includes mixed fixture/real-time events, current-version transitions, required/optional distinctions, demo-notice isolation, shared Dashboard identities/order, read-state reuse, unavailable sources, permissions/isolation, existing file/review flows and RO/EN screenshots under `artifacts/visual/e1c-007b/`; captures are ignored review evidence, not approved baselines.
