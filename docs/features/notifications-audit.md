# Notifications and Audit Activity (E1-010)

The authenticated Notifications page is available at `/notifications` and `/en/notifications`, with **Notificări** active in the shared navigation and a **Dashboard > Notificări** breadcrumb alongside its existing eyebrow. It follows [canonical mockup 10](../design/mockups/10-audit-activity.png): header and traceability callout, category tabs and date range, three operational summary cards and sections, and a separate audit journal timeline with a local CSV export. The visible `DEBIRO` brand follows the current text-only brand contract. English copy remains subject to product-owner review.

The typed demo snapshot keeps `NotificationActivityItem` (operational activity, including `isUnread`) separate from `AuditEvent` (read-only history with actor and timestamp). Expiring and missing-document summaries are distinct typed presentation records. All dates and category counts derive from a fixed fixture reference time; sample values are not live compliance calculations. Category tabs filter only notifications. The date range filters notifications and audit events independently. Summary links expand and focus their sections, and the audit export contains the currently date-filtered audit events in newest-first order. The CSV is generated locally; no reporting service or audit persistence exists.

The no-activity state is distinct from a filtered-empty state, which offers a reset action. The page uses synchronous fixtures, so it has no remote loading or error state. It does not mark items read, deliver notifications, send reminders, create/edit/delete audit records, or implement the later bell center. The browser-local demo has no authentication, backend, database, email, scheduled jobs, or authoritative vendor/document integration. At reduced widths the audit journal stacks below the operational sections, while tabs and tables scroll within their own bounds instead of widening the document. No screenshot baseline has been approved or committed.
