# Supplier Upload Portal (E1-008)

The external supplier experience at `/upload/demo-construct-pro` and `/en/upload/demo-construct-pro` implements [canonical mockup 08](../design/mockups/08-supplier-upload-portal.png). It has its own brand-and-locale header, invitation context, requested-document list with fixture status/progress, security and help panels, decorative mountain treatment, and footer. It does **not** use the authenticated app shell or require a supplier account. The [Invite Vendor drawer](invite-vendor.md) displays a demo URL for this route and opens the local preview in a separate tab.

The route accepts a token-shaped segment, but only the deterministic `demo-construct-pro` fixture resolves; unknown values return 404. This is a lookup of presentation data, **not** token validation or access control. The requesting organization, supplier, documents, uploaded sample rows, and help contacts are typed fixture data. The initial progress derives from the two fixture-uploaded rows (2 of 4, 50%), correcting the mockup's inconsistent `0 din 4` label while preserving its hierarchy. Romanian copy follows the approved image; temporary ComplyHub branding is replaced with plain `DEBIRO`. English copy awaits product-owner review.

The pending/missing document controls accept a browser-local PDF, JPG, JPEG, or PNG selection up to the mockup's 10 MB limit. The interface associates type/size errors with the relevant input and shows the selected filename as **selected locally**, not uploaded. Selection never increments the fixture-uploaded progress, is lost on reload, and sends no network request. The sample uploaded rows are display-only. The security statements reproduce canonical mockup copy; they do not describe an implemented secure upload service. Privacy/terms and uploaded-row action affordances remain inactive because their destinations/actions are not defined.

There is no real invitation issuance, signed-token validation, expiry/revocation enforcement, supplier authorization, private object storage, upload API, document review, OCR/AI, notification, or email delivery. A future server boundary must validate scoped invitation capabilities before serving private supplier data or accepting uploads, then write files to authorized private storage and replace these fixtures/local states. The existing demo URL must never be treated as a production capability.
