# Company Documents (E1C-002 / E1C-003 / E1C-003A / E1C-003B)

`/company/documents` and `/en/company/documents` are a separate company-owned listing, following the supplied `docs/design/mockups/company-documents.png` reference. Romanian locale follows the existing as-needed prefix convention (`/ro/...` resolves to the same destination). The supplied mockups remain untracked and untouched. The shared authenticated shell, page header, breadcrumb root override, SummaryMetricCard, Surface, StatusBadge, Avatar, SearchInput, SelectField, FilterPanel, Tooltip, Button and RowActionMenu are reused. There was no shared pagination component; the small shared Pagination primitive follows the existing authenticated previous/page/next and page-size pattern without refactoring existing tables.

The expandable **Companie / Company** group sits between Documents and Templates. Its Company Documents and Employees children use locale-aware links; the active child and parent styling derive from pathname. Explicit expansion is independent from other sections and Company Settings. Entering a child route reveals the group, while an explicit collapse on the same route remains possible. Existing sidebar dimensions, compact horizontal navigation, settings submenu, Reports availability, top utilities and switcher are unchanged. This section uses the explicitly requested **Companie > Documente companie / Company > Company Documents** breadcrumb root, without changing existing Dashboard/Profile-root breadcrumbs. `/company/employees` and its EN equivalent are accessible localized Coming Soon routes, not Employee management.

## Read model and ownership

The minimal listing contract lives in `features/company-documents/types.ts`. `CompanyDocumentRecord` reuses relevant `CreatedDocument` metadata/review/version fields through `Pick`; it does not generalize or replace the vendor-bound upload domain. Separate `CompanyDocumentRequirement` records hold requiredness, the existing expiry-warning enum and an explicit current-document reference. The public `CompanyDocumentListRow` distinguishes requirement ID, current document ID, status, nullable issuer/dates/updater, and actual file availability. ISO dates and nulls remain domain values, not display strings. The pure projection only reads the requested company workspace; the session/page boundary additionally uses existing active-membership access checks.

`debiro.company-documents-session` owns the company metadata, definitions and private company-keyed file sidecars. E1C-003 extends this same owner rather than creating a parallel store or migrating/resetting companies, vendor files, requirements or templates. Client navigation, locale changes, component/module reinitialization and company switch/return preserve the existing tab-local lifetime. Reload/new tabs restore initial fixtures; local metadata and bytes do not survive that boundary. No File/Blob JSON serialization or durable storage is claimed. New companies and the secondary demo company start empty. Saving a Company-scoped template does not automatically create requirements here.

Only Demo owns six deterministic sample requirements and five current metadata records, plus one historical record. Stable `company-requirement:` / `company-document:` identities do not overlap vendor fixtures. Dates use the shared E1 reference date and actors reuse existing demo-member display names. There are **no seeded file bytes or share links**. A metadata record may represent an uploaded current document while honestly lacking downloadable bytes in this listing demo. Invalid/foreign/malformed entries produce the existing localized ErrorState, never vendor fallback or a destructive repair. Empty owned state and filtered-empty state are distinct.

## Status, metrics and interaction

Only non-superseded, non-rejected current documents satisfy a requirement or drive status; for managed versions with an explicit requirement ID, the requirement's current pointer is authoritative. Unreferenced history never becomes a second unassociated current file. No current document means Missing; pending review means Needs Review; approved documents use the existing `approvedCompliance` and calendar-day utilities, including configured warning thresholds and manual-expiry semantics. No Uploaded substitute or new review/compliance rule is introduced. Legacy unassociated current documents can still be listed without inventing a requirement. Existing vendor ownership, review, compliance, snapshots and files remain unchanged.

Total Documents counts distinct current document IDs, excluding missing obligations/history. Needs Attention counts each logical requirement (or unassociated current document) once for required-missing, expired, pending-review or expiring-soon; optional-missing does not count. Active Shares is explicitly zero because no sharing domain exists. No illustrative growth value is shown. KPIs remain based on all owned rows, not the filtered page.

Search normalizes case, accents and surrounding whitespace over localized name, displayed document type and issuer. Type/status filters combine with search. The canonical inline controls and the shared FilterPanel edit the same state; its reset preserves query, while no-results recovery clears query and filters. Name, status, expiration and updated-date sorting use deterministic name/ID ties; null dates stay last in either direction. Default expiration order is ascending. Pagination starts at ten rows, supports 20/50, derives page counts from filtered rows and resets on filter/page-size/sort changes. Tables use the existing focusable horizontal-scroll pattern, never page-level overflow.

Selection is local UI state keyed to both requirement and current-version identity, retained across pages with an accurate count. Only rows with a current document and real nonempty company-owned file bytes are eligible. Missing/history/metadata-only files cannot enter selection; replacement/rejection/removed availability invalidates stale selection rather than silently selecting replacement bytes. Select-page, mixed state, individual toggles and Deselect all are supported. Company switching unmounts management/preview/selection/filter UI before entering the target Dashboard; global Profile/Invitations behavior is unchanged.

## Management, versions and review

E1C-003 enables Add Document, missing-requirement upload, Details, replacement, metadata editing, human confirmation/rejection, manual expiry, actual current/historical downloads and bulk individual downloads. These use `management.ts` company-owned operations, never vendor request handlers or vendor-specific routes. Administrator membership is required for upload/template application/replacement/metadata/manual expiry; Administrator or Reviewer can review; all active company members can read/download. The operation boundaries recheck access, company/requirement/current identity, input validity and file availability, not only disabled UI. Invalid/stale/corrupt/foreign operations preserve current records, history and bytes.

The adapted Add Document drawer reuses the existing DocumentUploadDrawer shell and extracted owner-neutral DocumentFileDropzone. Its localized session notice explicitly warns that reload loses local documents/files. PDF/JPG/JPEG/PNG, extension/MIME and 10 MiB checks reuse `uploadFileError`; company uploads additionally reject empty files. E1C-003A gives this single drawer three explicit invocation contexts: standalone upload from the page header, upload for a missing requirement row, and new version of an existing current document. Standalone uploads require file/name/type and create an associated optional company requirement internally. Bound uploads show prepopulated read-only document name/type, preserve the existing requirement identity/requiredness, and never create a second requirement. Issuer and expiry remain optional. No upload context exposes a requirement selector, independent-document terminology, required checkbox or template application. Stale bound identities fail without falling back to standalone creation. Current-document rows retain the established Upload New Version flow and history behavior.

The visible **Setează documente din șablon / Set Documents from Template** action in the document-list header opens the existing template-selection/application flow in its own shared Drawer, separate from file upload and outside the main page-header actions. It reuses Vendor Details' Button size/icon and shared label; the former page overflow entry is removed. It creates missing document requirements only, never uploaded versions or file bytes. Empty-template, success, repeat/no-new-documents and recoverable error states are localized; closing restores focus, and company switching clears this UI. An Administrator-only empty-state link enters the existing Templates workspace. Only owned `scope=company` definitions are accepted. The same `applyCompanyTemplate` operation and template/type resolution helpers are reused, without a parallel workflow or domain model change. A `(templateId, templateRequirementId)` snapshot is instantiated once, preserving existing snapshots when a template is edited or applied again. Vendor/Employee templates and foreign custom types are denied. Existing Administrator permissions and company isolation are unchanged. Company-only layout classes reuse the existing 1199px header reflow convention, reserve the upload close-control area, and stack upload actions at 375px and below so the full Romanian CTA remains readable; optional shared class slots leave every other consumer unchanged.

E1C-003B reuses compact Field/SelectField controls across upload contexts, metadata editing and template selection, with standard read-only/error/focus styling. Native editable selects use the normal white control surface rather than accidentally matching the shared read-only selector. The existing shared PageHeader/SearchInput/Pagination remain intact; the document KPI variant, shared Vendor Details table presentation and document StatusBadge/Button sizes replace the larger Dashboard treatment and local table typography. Company's three KPIs, columns, status colors/meanings, current-version selection and pagination remain company-owned and unchanged. Documents' compact table and Vendors' count-only KPI density are documented intentional variants, not targets for an unrelated global redesign; see [shared UI reuse](../design/ui-foundation.md#company-and-employee-ui-reuse-e1c-003b).

E1C-003C adds Source after Document in this same table. Existing `(templateId, templateRequirementId)` links resolve only owned company-scoped templates through the shared template-source resolver; no document-name inference, new association model or company-template merge behavior is introduced. A valid source uses the shared readable source badge and matching subtle full-row tint; manual rows remain neutral, while unresolved provenance is explicitly unavailable. Current template names follow the existing link rather than adding new name snapshots. Renaming keeps the template accent stable. The existing focusable horizontally scrolling table accommodates the extra column without page-level overflow. Checkbox selection overrides grouping tint with a visible selected indication; focus/hover, red expired badges, every filter/sort/pagination operation, file/version lifecycle and existing sharing controls remain independent.

New versions carry requirement/company IDs, a distinct stable ID, monotonically increasing per-requirement version, original filename/type/size/upload timestamp/actor, nullable review metadata/rejection reason and existing version-link/manual-expiry fields. Old E1C-002 records remain readable through their current/supersession chain without destructive migration or invented provenance. The selected version ID is the file reference. Upload/replacement atomically commits a pending current version and exact File to the existing company file sidecar. Replaced records keep original metadata and bytes. Rejection requires a trimmed nonempty reason, keeps that version/history/file, and clears the current pointer. Previously superseded approved history is not automatically promoted to current. Missing optional requirements still do not contribute Attention.

Name/issuer/expiry edits apply only to the current version, preserve immutable upload identity/provenance/bytes/version and reset changed review-relevant metadata to pending with cleared confirmation fields. Existing localized names are preserved when unchanged. Manual expiry reuses `canManuallyExpire`/`approvedCompliance`: only approved current Valid/Expiring Soon files qualify; repeats fail. It records a separate override, never a fake expiry date or a new version. Replacement starts a fresh pending version without inheriting that override. Company replacements intentionally require review; existing vendor internal renewals remain date-derived without review.

Details and newest-first History reuse extracted owner-neutral DocumentFileCard/DocumentVersionHistory presentation and the existing drawer styles/headers/size/focus/scroll behavior. Company-specific metadata/review actions are additive adaptations; no vendor labels or fake legal/AI verification appear. History includes actual filename/provenance, current/historical identity, review outcome/rejection reason and expiry. Available historical files can be viewed/downloaded read-only. Browser-native PDF/raster preview uses only authorized real bytes and revokes temporary object URLs on exit/switch; missing bytes never acquire a sample preview. The shared browser download boundary preserves actual original bytes/filenames and revokes URLs. Bulk downloads are individual browser downloads, not an invented archive. Browser PDF rendering and multiple-download policies remain browser capabilities.

PDF preview requires an explicitly reported native PDF capability; unsupported/unknown browsers (including Playwright's default headless shell) receive a localized explanation and the original-file Download action, never a blank/successful-looking substitute. Full Chromium separately verifies its real native PDF viewer and URL revocation on company switch. Native PDF plugins cannot run in sandboxed iframes, so the PDF frame accepts only the authorized Blob, explicitly forced to `application/pdf`, with no referrer; arbitrary URLs/HTML are never embedded. Raster files use the browser image decoder with an error fallback. This is browser-native viewing, not a new custom renderer, security scanner or production file-validation guarantee.

Secure sharing remains E1C-004: existing localized unavailable Tooltips remain on header/row/bulk Share, and Active Shares stays zero. No link, delivery notification, public endpoint, OCR/AI, backend storage, company Dashboard/search/notification aggregation or hard delete is added. Future company integrations remain separate from the existing vendor sources.

## Validation and future boundaries

Unit/component/browser coverage includes current/history/missing/optional rows, review/expiry boundaries, nullable/malformed state, derived totals, combined filters, deterministic sorting, eligibility/pagination/selection, navigation, actual-byte upload/history/download, invalid-operation rollback, template snapshots, permissions, company switching, unchanged vendor sources and RO/EN. E1C-003B captures compare Vendors/Documents/Company Documents at identical scale and assert actual computed form, KPI, table, badge and action typography, including focus/validation/read-only states. E1C-003C adds stable-accent allocation/backfill, palette contrast, explicit scoped provenance, source labels, row/selection/focus colors, rename/navigation/locale/company stability and before/after Vendor header measurements. All three simplified upload contexts and separate idempotent template application remain covered. Shared component geometry takes precedence over duplicating mockup controls. Explicit task rules supersede illustrative Uploaded badges, growth/sharing counts, stale dates, deletion affordances and unsupported sharing actions.

No HTTP API or analytics dependency is implemented. The task reserves a future authenticated `GET /company-documents` listing with search/status/documentType/sort/page/pageSize parameters; company scope must come from authorized workspace context, not a trusted arbitrary client company ID. There is no existing analytics abstraction to call. The future non-sensitive event names are `company_documents_viewed`, `company_documents_filtered` and `company_documents_selected`; document names and file contents must not be emitted. These are deferred boundaries, not active backend/security/tracking guarantees. Existing local membership checks are not server authorization.

E1C-003 additionally reserves future POST/GET/PATCH `/company-documents[/:id]`, POST/GET `/:id/versions`, POST `/:id/review` and POST `/:id/expire`; none are implemented HTTP endpoints. Future errors distinguish invalid input (400), unauthenticated/unauthorized (401/403), absent or inaccessible records (404), conflicting current state (409), oversized files (413) and unsupported types (415). E1 operations return localized-safe reason codes, not file paths or fake network responses.
