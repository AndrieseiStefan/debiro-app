# Onboarding Screen

E1-002 implements the first-step screen in [canonical mockup 02](../design/mockups/02-onboarding.png) at `/onboarding` and `/en/onboarding`; E1-012 extends that same shell with [Step 2](../design/mockups/12-onboarding-step2.png) and [Step 3](../design/mockups/13-onboarding-step3.png). The approved layout remains the reference, while E1-012A/B explicitly supersede the optional-step defaults, Step 2/3 labels, and Step 3 invitation copy/actions shown in those images. Placeholder branding is replaced by `DEBIRO`; English is translated for review. The page reuses PublicHeader, Button, Field, Surface, and Divider. A deterministic typed fixture supplies visible sample values; editing, password visibility, native required-field/password-rule validation, and terms selection are local to the browser.

Step 1 is mandatory: Continue is enabled only while every required field, the password rules, and the Terms agreement are valid. Steps 2 and 3 are labelled optional. Step 2 opens with no template or documents selected; its recommended construction template is only a suggestion. Choosing a template applies local checklist defaults, and selecting a document directly is also an explicit configuration. Continue is available only while at least one document is selected and preserves that local draft in Step 3; Configure later clears the draft before proceeding. Step 3 adds suppliers but does not invite them. It opens with no suppliers and supports adding or removing local rows. Back returns to Step 2 without losing the local onboarding state. Go to Dashboard works with zero suppliers or valid supplier rows; a started but incomplete row must be completed or removed before either exit. All three steps stay on the same route; refresh resets the fixture flow. E1-031 retains intentional setup in company-owned tab memory as described below; no invitation is sent, and no account, authentication, backend, API or durable persistence is created. Selectors reuse the shared company options described below. The shared top header omits the former secondary brand tagline and contains only `DEBIRO`, help, and RO/EN; help moves to a centered second row when those elements no longer fit. Help and legal text have no destinations yet.

E1-030 binds all five company-owned Step 1 fields to the shared Company on valid completion, with duplicate-CUI validation and no global-user/auth data copied into Company. The existing industry/country choices from company creation and the approved size choice share stable IDs across Onboarding, My Companies and Company Profile. Company values remain editable from [Company Profile](company-profile.md), which documents the complete field-ownership audit. E1-031 completion initializes selected construction starter/document configuration only for that company. General/direct selections remain an ordinary Requirements draft until the required vendor category is selected (explicit product-owner decision). Supplier name/email rows lack mandatory CUI/category and remain ordinary company-owned Add Vendor drafts for later completion, never fabricated Vendor entities. Configure later creates no operational records. See [Company workspace setup](company-workspaces.md#onboarding-setup); no identity, durable persistence or delivery is introduced.

The desktop mountain landscape is a generated decorative approximation; the right quote illustrations are built in CSS, including simplified construction and supplier motifs for Steps 2 and 3 because exact source artwork is unavailable. Neither the mockup nor a captured screenshot is rendered as the interface. Responsive reflow follows the [UI foundation](../design/ui-foundation.md#responsive-contract). Generated visual captures remain unapproved and ignored.
