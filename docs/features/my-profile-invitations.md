# My Profile and My Invitations (E1-032A)

`/profile`, `/invitations` and their `/en/...` equivalents are global-user pages. Both use the existing authenticated shell, shared breadcrumbs and page header; neither changes the active company. E1-032A1 overrides the pictured Dashboard parent: My Profile uses **Profil / Profile** alone; My Invitations uses **Profil > Invitațiile mele / Profile > My Invitations**, with a locale-preserving parent link to My Profile. Composition and Romanian copy follow [My Profile](../design/mockups/32a-my-profile.png) and [My Invitations](../design/mockups/32a-my-invitations.png). The existing shell, shared controls and reduced profile dropdown take precedence over the pictured shell/menu. English copy and final visual approval remain pending.

## Profile ownership and editing

`user-profile-state.ts` extends the existing fixture identity (stable user ID/email), not a second auth account. First/last name and optional phone use shared Field controls; names are trimmed/nonempty and phone retains existing permissive `tel` rules. Email is read-only and checked with the shared email validator. Save is disabled when unchanged/invalid; Cancel restores saved values. Successful Save updates the shared global identity, initials, dropdown, company footer, My Companies initial administrator, current-user membership displays, Dashboard greeting and new local action actors. Stored historical audit, document uploader/reviewer and note author snapshots are not rewritten. Live membership labels are projections, not edits to company business metadata. Company Profile remains independently company-owned.

Language is the existing next-intl route locale, not a second stored preference. The select navigates to the locale-equivalent Profile route and the top-bar locale links update it. Email notifications and periodic summaries are boolean user preferences in the existing tab-memory model, without email/scheduling services. Unsaved personal-field navigation uses the existing Profile confirmation/Back guard, including locale changes and actual navigation away. Company switching is not navigation on this global page: it bypasses discard confirmation and preserves the current draft. Preferences save synchronously independently of the personal-fields draft.

There is no working auth-provider security/password-change flow or avatar upload in E1. The camera affordance, fabricated verified-email badge/password date and unsupported security action/section are omitted, rather than pretending they work. The existing plain phone field takes precedence over the mockup's unsupported country-code picker. No credentials, custom email migration or auth/session semantics are introduced.

## Received invitations and access

`invitations-state.ts` owns received invitation records globally, selected by the current identity's case-insensitive email. This is distinct from company-owned outgoing member invitation simulation. Initial records include one active invitation, one expired pending invitation and one accepted historical invitation whose company already has membership. Company/inviter sample data is not locked mockup copy.

The page KPIs, filter and dropdown badge use the same identity-scoped projection. Pending becomes expired only when the existing deterministic E1 reference time exceeds `expiresAt`; accepted/rejected history remains resolved. Calendar-day countdown and exact dates use the existing fixture-clock helpers. Only pending, unexpired rows expose Accept/Reject. Status filters include all, active, accepted, expired and rejected. True zero uses shared EmptyState without a CTA; filtered zero is distinct. Feedback follows existing local inline status/alert patterns, without fake loading or network toasts.

Invitation columns align on desktop, with sufficient intrinsic space for the existing role badges/actions. Reduced cards use equal-width metadata columns, then stack on narrow content widths. Geometry coverage checks field separation and full role-icon size, not only page-level overflow.

Acceptance synchronously revalidates pending state, expiry, identity and the available company record before adding/reusing access through `company-state.ts`. New access uses the existing Company and CompanyMembership models and proposed role. An existing active membership wins unchanged; invited membership can become active without duplication. The invitation becomes accepted; My Companies/switcher and counts update. **Active company and route do not change.** Explicit later switching preserves the current Profile-area route under E1-032A1; company-scoped switches still use E1-031B's locale-matched Dashboard entry. New access gets no Demo operational records or billing history. Rejection uses shared ConfirmationDialog, retains historical status/date and grants no access. Invalid, resolved, expired, wrong-identity and unavailable-company actions fail without mutations.

User edits/preferences, received-invitation history and access survive SPA/locale/company switching through `browserSession`; full reload/new tabs reset the local demo. No backend, auth, invitation delivery or durable persistence is added.

## Component reuse and validation

Reused: AuthenticatedAppShell, AuthenticatedPageHeader, AuthenticatedBreadcrumbs, Surface, Field/SelectField, Button, RoleBadge, StatusBadge, ConfirmationDialog, EmptyState, AppIcon, locale routing and dirty-navigation guard. Existing Dashboard KPI, profile-menu initials and Invite Vendor toggle treatments are exposed as reusable SummaryMetricCard, Avatar and Switch implementations; their original consumers retain geometry/semantics. No page-local copies of generic controls or new visual system were created.

State units cover identity ownership/propagation, validation/preferences, historical actors, expiry boundaries, zero/count projections, acceptance/reuse/rejection and atomic failures. Browser tests cover RO/EN pages and dropdown links, keyboard/focus, Save/Cancel/dirty navigation, locale synchronization, membership/switcher integration, Profile-root links, retained drafts/filters on company switch, no automatic workspace switch, history/filter/badge updates and containment at 1448/1200/1024/768/758/600/375/320 widths. Existing dropdown, company-switch, My Companies, Company Profile, Members, Onboarding, Dashboard and Invite Vendor regressions remain covered. Captures are ignored/unapproved review artifacts, not accepted baselines.
