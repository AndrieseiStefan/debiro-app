# Architecture Decision Records

Use an ADR for durable architecture or product-engineering decisions with meaningful alternatives. Number ADRs sequentially and keep their status explicit.

## Format

1. Title
2. Status
3. Context
4. Options considered
5. Decision
6. Trade-offs
7. Consequences
8. Risks
9. Follow-up

Accepted ADRs describe current decisions. Git history preserves their evolution; supersede decisions explicitly rather than silently rewriting project truth.
