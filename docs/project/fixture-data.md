Demo Company starts Professional/trialing with twelve days; newly created companies start Starter/trialing with fourteen; Global Clean starts Business/active. `src/lib/fixture-clock.ts` supplies the E1 document/status reference: **2026-10-02, 12:00 UTC**. Seed dates, existing Vendor mutation timestamps and expiry captures retain it. Employee activity already records real timestamps. E1C-007B uses the latest authorized actual active-company event, with the fixture reference as a minimum, only for Notifications/Activity/Audit date filtering. Original timestamps and global clocks are never rewritten. UTC calendar-day differences remain independent of locale/time/DST. Expiry retains configured warning periods and the existing 30-day default.

Documents cards, tab badges and rows use the same active company-owned records. E1-028A1 derives vendor compliance only from configured requirements and their owned current `uploadedDocumentId` references, in severity order Noncompliant → Attention → Compliant. Required missing/expired files are Noncompliant; linked pending-review/expiring-soon files or an In Review requirement need Attention; optional missing/expired files do not make a vendor Noncompliant. Zero configured requirements is Compliant (`În regulă`): there is currently no unsatisfied configured obligation, not a claim of verification. File ratios are informational only; unconfigured vendors' available files supply actual accepted/total counts, never fictitious 4/5 inventories. No requirements are invented for other fixture vendors. The initial active-vendor summary derives 24 total, 23 Compliant, 1 Attention (Construct Pro's pending required tax file), 0 Noncompliant. Next expiry is the earliest accepted current file's actual ISO date, including expired files and optional files, excluding pending/rejected/superseded/no-expiry records. Sorting uses that same ISO value. All counts every vendor; compliance cards count active vendors only.

Notifications and Dashboard share domain-aware current attention and actual activity. Upcoming contains only current classified Expiring Soon files; Company pending review belongs in attention. Missing includes required obligations only, with no invented deadlines (`—`). Seeded sent-reminder notices remain demo records in bell/notification-specific filters, not actual Activity/Audit/Dashboard/domain timelines/CSV. Original date-only uploads and real local/Employee operations keep source identity and time. Passive Company/Employee attention remains in page sections and never becomes a bell record; actual notification records alone supply bell rows and unread counts. No Company/Employee notices are seeded to populate the demo; isolated test fixtures cover their authorized navigation. See [Notifications](../features/notifications-audit.md). Global Documents attention remains current uploaded Needs Review/Expiring Soon/Expired files (10 initially); missing never becomes an uploaded-document row. E1-031 monthly helpers keep the fixture month; only empty Dashboard exposes Add Vendor as a first-run action.

RO/EN share records, IDs, timestamps and counts; only formatting/copy differs. Supplier status remains Missing / In review / Uploaded, separate from internal compliance. Template Preview remains illustrative and independent of actual vendor uploads, with normalized 2026 sample dates. All local state resets on reload; there is no backend, durable audit, file storage, OCR, reminder scheduling, authentication or authoritative verification.
