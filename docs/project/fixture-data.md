# E1 demo timeline and projections

`src/lib/fixture-clock.ts` supplies the single E1 reference: **2026-10-02, 12:00 UTC**. Seed dates, browser-memory mutation timestamps, date-range filters and deterministic captures use this reference. It is explicitly demo-only: no global/production clock is replaced. UTC calendar-day differences are independent of locale, time-of-day and DST. Pure expiry calculation takes an explicit clock and preserves the requirement's snapshotted warning period, with the existing 30-day default.

The initial Global Documents population is 24 current files: 4 pending review, 14 valid, 4 expiring soon, 2 expired. Pending review takes precedence over expiry metadata. Accepted no-expiry documents remain valid and have no invented expiry/countdown. Stable legacy route IDs and filenames are retained; their year suffixes are not interpreted as metadata dates. The separate Construct Pro liability file remains vendor-only. Rejected and superseded uploads remain history and are excluded from current rows, counts and expiry projections; reupload creates a new identity.

Documents cards, tab badges and rows use the same active company-owned records. E1-028A1 derives vendor compliance only from configured requirements and their owned current `uploadedDocumentId` references, in severity order Noncompliant → Attention → Compliant. Required missing/expired files are Noncompliant; linked pending-review/expiring-soon files or an In Review requirement need Attention; optional missing/expired files do not make a vendor Noncompliant. Zero configured requirements is Compliant (`În regulă`): there is currently no unsatisfied configured obligation, not a claim of verification. File ratios are informational only; unconfigured vendors' available files supply actual accepted/total counts, never fictitious 4/5 inventories. No requirements are invented for other fixture vendors. The initial active-vendor summary derives 24 total, 23 Compliant, 1 Attention (Construct Pro's pending required tax file), 0 Noncompliant. Next expiry is the earliest accepted current file's actual ISO date, including expired files and optional files, excluding pending/rejected/superseded/no-expiry records. Sorting uses that same ISO value. All counts every vendor; compliance cards count active vendors only.

Notifications expiry rows derive from accepted current documents; missing rows derive from actual requirements lacking a current file, including optional missing requirements as in Details. No requirement deadline exists in this model, so the deadline cell is `—`. Existing historical notices and date-only upload events share one audit source with Vendor Activity; matching upload notices are not duplicated. Recent activity also projects successful local audit actions without creating delivered/unread notifications. Audit, activity and bell date labels derive from timestamps/reference time, not independent rendered offsets. Dashboard's existing vendor metrics, expiry/missing table and supported recent-event kinds project the same sources; no new Dashboard status or interaction is introduced. The existing monthly comparison baselines remain historical sample values.

RO/EN share records, IDs, timestamps and counts; only formatting/copy differs. Supplier status remains Missing / In review / Uploaded, separate from internal compliance. Template Preview remains illustrative and independent of actual vendor uploads, with normalized 2026 sample dates. All local state resets on reload; there is no backend, durable audit, file storage, OCR, reminder scheduling, authentication or authoritative verification.
